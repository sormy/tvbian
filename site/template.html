02 / The system

Debian at heart.
Built for this hardware.

01 — THE FOUNDATION

A shell. How refreshing.

A command-line system based on Debian, with SSH and apt. Install what you need. The base image starts with a login prompt; it has no opinions about what you should watch.

02 — THE HARDWARE

The parts Debian can't know.

Debian supplies the base. TVBian supplies board configuration, kernels, drivers, and firmware. The test reports include the awkward bits. Optimism is not a driver.

03 — THE UPDATES

Keep it current with apt.

Debian packages and a signed TVBian repository for hardware support. Update with apt; fresh images arrive weekly. Installing everything again is a hobby, not a requirement.

The bar for a finished port

The login prompt is the starting line.

The AI works through the full bring-up procedure and fixes what it can. “It boots” is excellent news. There is still an entire computer attached to it.

  • The computer

    RAM, storage, physical ports, heat under load, reboots, suspend, and wake.

  • The connections

    Ethernet, Wi-Fi, Bluetooth, audio, the remote, buttons, and LEDs.

  • Every video engine

    Each hardware decoder and encoder: codecs, profiles, bit depths, sizes, and output checked against software.

  • The GPU

    3D rendering off-screen and on-screen, with the full graphics benchmark suite.

  • The display pipeline

    HDMI modes and refresh rates, HDR, hardware tone mapping, scaling, and multiple planes composing video and the interface.

  • The whole path

    Real video from decoder to screen, sustained frame rates, clean logs, and a few days of daily use.

Best effort. Honest results. The aim is hardware you can use straight after installation. We support a current kernel and an opt-in next kernel series. A finished bring-up records every check on both. What works, what's degraded, and what's broken goes in the board's test report, with the remaining gaps and limits spelled out.

03 / Make it better

One box is enough.

Bring the odd box on your desk. AI handles bring-up and review; you handle the steps that need hands.

01 — YOUR HANDS

You have opposable thumbs.

Connect serial, plug in cables, press buttons, and check the screen. The procedure tells you what to do. Your ability to hold a toothpick is finally a project dependency.

02 — AI BRING-UP

AI does the bring-up.

An AI coding agent inspects the factory firmware, builds, tests, and keeps the logs. It follows the full bring-up procedure through to the hardware checks. Someone has to read all those boot logs, and it volunteered.

03 — AI REVIEW

Content over form.

AI reviews the structure, hardware changes, and complete test report. Claims need results. Factory-derived trees can look factory-derived. This is a hardware project, not a device-tree calligraphy contest.

Known families and chips reuse shared support. New chips can need driver work.

  • Start with the factory's device tree.

    Decompile the shipped tree, patch what needs changing, and keep the evidence. You bought a TV box, not the company that designed it. Reconstructing the manufacturer's source tree is not your new unpaid job.

    Read the bring-up guide ↗

  • One board. One pull request.

    Board files, patches, and evidence arrive together here. No prerequisite PR relay across five repositories. You are adding a box, not applying for a mortgage. Shared fixes go upstream separately.

    Pull requests ↗

  • Give a box a purpose.

    Got an unsupported box in a drawer? Give it a second career in development. Send the model and board details. The drawer will manage without it.

    Offer hardware ↗

  • Be our second opinion.

    Test an update and report what works. Include the exact board and image. “It did a weird thing” is a promising opening sentence; we will need the rest of the story.

    Report test results ↗
